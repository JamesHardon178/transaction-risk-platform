## 0:00–0:40 开场：业务问题与数据

**素材**：看板第一页「数据概览」（`docs/screenshots/01_overview.png`）

说词要点：
- 数据：Kaggle 公开的真实信用卡交易，284,807 笔、48 小时、31 字段；欺诈仅 492 笔（0.17%），**1 : 578 不平衡**；
- 一句话点题："在这种比例下，把所有交易判为正常就有 99.83% 的 Accuracy——所以这个项目从头到尾不用 Accuracy。"
- 顺带说明数据质量动作：零缺失，1,081 行重复已去重（283,726 行），原始数据只读。

## 0:40–1:40 EDA：三个反直觉发现

**素材**：`reports/figures/fig02_amount_distribution.png`、`fig03_hourly_pattern.png`、`fig07_key_features.png`

1. **欺诈金额更小**：欺诈中位数 9.25€ < 正常 22.00€（Mann-Whitney p=8.6e-06，但效应量只有 -0.1159）——"统计显著 ≠ 单特征可区分"；
2. **时段**：相对第 2 时段欺诈率 1.71%，是全局的约 10 倍；
3. **特征**：V17/V14/V12/V10 上欺诈类整体左移 4~7 个标准差，是最强信号；
4. 加分项（主动讲负面结论）：相邻交易间隔在两类间无区分力，**没有进特征池**——省掉一轮无效特征工程。

## 1:40–3:00 建模与评估：口径比模型更重要

**素材**：看板「模型评估」页（`docs/screenshots/02_models.png`）+ `fig10_val_pr.png`

- 切分：按时间 70/15/15，"用过去训练、对未来评估"，禁用随机切分；验证集只有 55 笔欺诈——每笔影响 Recall 约 1.8pp，所以结论以方向和混淆计数为主；
- 三个模型：LR（class_weight）/ RF（balanced_subsample）/ XGB（scale_pos_weight=541.6），**不用 SMOTE**（PCA 特征线性插值不合理）；
- 关键对比：ROC-AUC 三者都 >0.97 肉眼难分，**PR-AUC 才拉开差距**（RF 0.8735 > XGB 0.8646 > LR 0.8367）——极端不平衡下 FPR 被海量真负样本稀释；
- 诚实边界：RF 与 XGB 差距 0.0089，在 55 笔的抽样噪声内，不声称"RF 显著更优"。

## 3:00–4:20 阈值与成本优化（全场重点）

**素材**：看板「风险阈值分析」页（`03_threshold.png`）→「策略成本优化」页（`04_strategy.png`）+ `fig17_cost_curve.png`、`fig20_sensitivity_heatmap.png`

- 现场拖动阈值滑块：Precision/Recall/混淆矩阵实时重算——"模型能力是 ROC 曲线，工作点是曲线上的一个点，**这是两件事**"；
- 成本模型：总成本 = FN×漏判成本 + FP×误拦成本（**100/5 是实验假设**，页面有声明）；
- 结果：默认 0.5 成本 1,400 → 成本最优 0.144 成本 735，**降 47.5%**；
- 三策略（规则先于数据写死）：保守 0.041（Recall 90.9%）/ 平衡 0.144（成本最小）/ 激进 0.287（Precision 95.7%）；
- 现场把漏判成本从 100 改成 5000：最优阈值滑向 0.017——"**最优阈值是成本结构的函数，不是常数**"（敏感性热力图 fig20 一图讲完）；
- 冻结与纪律：选定 RF+0.144 后测试集只评一次：成本 1,465（+99.3%）。**主动讲**："测试集上激进策略更便宜，但回头改选就是在用测试集调参，我不做。"——差异来自 55/52 笔的小样本噪声与可能的时间漂移。

## 4:20–5:00 收尾：诚实边界 + 工程质量

**素材**：看板「风险分析报告」页（`05_report.png`）

- 局限性（说 3 条即可）：成本参数是实验假设；48 小时数据无法验证漂移；评估样本小（55/52 笔欺诈）；
- 工程质量一句话带过：58 个 pytest 用例、两本 Notebook 从头重跑零报错且指标逐位复现、9 条 SQL（CTE/窗口函数）结果逐字节一致、五页看板全部由真实产物驱动、无硬编码指标；
- 结束语："这个项目的价值不是给出一个'最优阈值'，而是把**假设 → 工作点**的映射做成可配置、可复现的工具。"

## 备用问答弹药（演示中被追问时用）

- 为什么时间切分而不是分层随机切分？→ 防泄漏 + 模拟上线；随机切分会把未来信息泄进训练集。
- 为什么 PR-AUC 不用 `auc(recall, precision)`？→ 梯形法对 PR 曲线的锯齿会低估，`average_precision_score` 是标准口径。
- 为什么不用 SMOTE？→ V1-V28 是 PCA 坐标，插值不在真实流形上；且破坏 48 小时时间结构；代价加权足够。
- 测试集成本为什么翻倍？→ 55/52 笔欺诈的抽样噪声 + 可能的时间漂移；FP 侧稳定（27→33）说明对正常交易的判断更稳。
- 下一步会做什么？→ 概率校准（isotonic/Platt）、StratifiedGroupKFold 时间序列多折、SHAP 归因、上线后周度监控。
